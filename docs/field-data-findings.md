# Field data findings — MDVizio-X, 2026-07-11 site

Every study the site produced on 2026-07-11: **160 studies, 11.54 GB**, read from
`D:\필피핀_실사_데이터\정제_데이터\데이터\통합_데이터`. Each study holds `org.dcm`,
`viewer.dcm`, `ai.dcm`, `ai_heatmap.dcm`, `thumb.png` and `ai_result.txt`; the DICOM
headers and the result files were parsed in full, not sampled.

This was written while designing the survey-to-worklist integration. Most of what follows
is about the imaging pipeline rather than that integration, and is here because the data
was in front of us. Items 1 and 2 are the ones worth someone's afternoon.

## 1. The TB threshold takes three different values

`ai_result.txt` records the thresholds each analysis ran with. Every other threshold is
`0.5` in all 160 files. `ai_th_tb` is not:

| `ai_th_tb` | Studies | Of those flagged `is_sick`, how many got `active_tb > 0` |
|---|---|---|
| `0.4` | 84 | 17 of 25 |
| `0.5` | 17 | 11 of 11 |
| `50.0` | 59 | **1 of 11** |

Same day, same site, same operator account.

**A hypothesis that fits the numbers.** The consumer appears to scale thresholds by 100:
`ai_th_abnormal` is `0.5` in every file, and `is_sick` separates cleanly at 50 % —
`is_sick` is true for every study with Abnormal ≥ 57.76 % and false for every study at or
below 35.96 %, with nothing in between. If the same ×100 is applied to `ai_th_tb = 50.0`,
the effective threshold becomes 5000 and no image can ever clear it. The 1-of-11 row is
what that would look like.

If that is what is happening, **59 studies — 37 % of the day — were never meaningfully
assessed for active TB.** Confirming it means looking at the code that reads these
fields, not at more data.

The scale mismatch shows up elsewhere too: `active_tb` and `inactive_tb` are percentages
(observed range 0.00015 to 100.0) while `ai_th_tb_active` is `0.5`.

## 2. 71 % of patients have no TB probability at all

The `ai_result` array carries five diseases when the study is flagged, and only
`Abnormal` when it is not:

| Detail | Studies |
|---|---|
| 5 diseases (Abnormal, Tuberculosis, Pneumonia, Pneumothorax, Mass) | 47 |
| `Abnormal` only | **113** |

So a tuberculosis screening programme produces no tuberculosis number for 113 of 160
patients. Everything depends on a general "Abnormal" gate at 50 %, and the highest
Abnormal score in the entire day is 67.6 % — the model never approaches certainty, so
where that gate sits matters more than it looks.

Whether this is intended is a question for whoever specified it; from outside it reads
like a screening test that mostly declines to answer the question it was bought for.

## 3. The AI image loses the patient — 160 of 160

`ai.dcm` is regenerated by LEADTOOLS (`(0002,0016) LEADTOOLS`, `v17.5`) and comes out
carrying that library's sample identity instead of the patient's:

| | `org.dcm` | `ai.dcm` |
|---|---|---|
| Patient Name | `BONUS, JAYCEL` | `John^Doe` |
| Patient ID | `20267111172324` | `123-45-6789` |
| Birth Date / Sex | `19951112` / `F` | `19970112` / `M` |
| Accession | `20267111792701` | `1` |
| Modality | `DX` | `OT` |
| Study Instance UID | `1.2.826.0.1.3680043…` | `1.2.840.114257.1…` (unrelated) |
| Specific Character Set | `ISO 2022 IR 149` | absent |
| MDAI private block | present | absent |

Not a sample: **every one of the 160**. `viewer.dcm` and `ai_heatmap.dcm` keep the correct
identity and differ from `org.dcm` only in window centre/width and a
`(0028,2110) Lossy Image Compression` element.

An image annotated with an AI finding, carrying a fabricated name and a US
social-security-shaped ID, is a problem before anyone mentions integration. Sent to PACS
it becomes a study belonging to nobody.

**It also decides how far the survey travels.** The survey the bridge attaches to the
worklist reaches `org.dcm`, `viewer.dcm` and `ai_heatmap.dcm` — and stops at `ai.dcm`
along with everything else. If the AI-annotated image is what goes to reading or to PACS,
the answers do not go with it.

## 4. Seven studies have AI results that never reached the header

Seven studies (4.4 %) have an `ai_result.txt` with scores but no MDAI private block in
`org.dcm`, and no `ai_heatmap.dcm`. One of the seven is `is_sick = true` with Abnormal
58.6 % — an abnormal finding that exists only in a sidecar text file.

## What this changes for the survey integration

| | |
|---|---|
| Modality default `DX` | Confirmed by 160/160 — already changed |
| Sending SPS Status `SCHEDULED` | Needed. The console never updates the status itself; it is `IN PROGRESS` on every image of the day |
| Private block `1001` under `MDAI_PRIVATE_CREATOR` | Confirmed as the house convention — already aligned |
| Character set | The risk is real but not urgent: all 160 names are ASCII, `PENARANDA` rather than `PEÑARANDA` |
| Survey lost at `ai.dcm` | Open. Depends on which image the reading workflow uses |
| Site storage | 10.8 GB/day is an operations question the survey database (a few MB) does not touch |
